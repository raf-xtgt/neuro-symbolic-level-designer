# Z Legend Game: Flutter Web + Flame Isometric Game

This folder holds the browser game and the Level Designer UI for the neuro-symbolic level designer.
Read `../ARCHITECTURE.md` for the level generation system and `../../game-assets/ASSET_SPEC.md` for the asset format.

## Architecture (decision: `../../BUILD_LOG.md` Log-8)

```
Flutter web app (z_legend_game_flutter)
 ├─ Level Designer screen ──HTTP──► Python FastAPI backend (../backend)
 │                                   └─ Pipelines 1-3 (Ingestion, Planning, Execution)
 └─ Game screen (Flame) ◄── level bundle (level.tmj, tileset.tsj, tileset.png)
```

* **Frontend:** one Flutter web app. It contains the Level Designer screen and the Flame game screen.
* **Backend:** Python + FastAPI in `../backend/`. It is not in this folder.
* **"Try Out":** the game loads the generated level bundle from the backend URL at runtime, not from bundled Flutter assets.

## Game Rules

* Target platform: **web** (Chrome). Do not use packages or APIs that do not work on Flutter web (for example `dart:io` file access).
* Engine: `flame` + `flame_tiled`. Follow `../.bob/rules/flame_isometric_rules.md`.
* Map format: Tiled JSON (`.tmj` / `.tsj`), orientation `isometric`, tile size 64 x 32.
* **Isometric object coordinates:** in a `.tmj`, object `x` and `y` are both in tile-height units (x = col * 32, y = row * 32 for 64 x 32 tiles). Convert them to screen space with the isometric projection. Do not treat them as screen pixels.
* Entity object types in the `Entities` layer: `PlayerSpawn`, `Zombie`, `ExitTrigger`.
* Characters: 8 directions (S, SW, W, NW, N, NE, E, SE), one sheet per animation (`idle`, `walk`, `attack`, `die`). Rows are directions, columns are frames. Read frame size, frame count, fps, and anchor from the sidecar JSON. Do not hard-code them.
* Place characters by their sidecar `anchor` (feet position), not by the frame's top-left corner.
* Depth sorting: priority from `X + Y + Z` (see the Bob rule).
