## Goal
Make the starter level playable in the browser. The Flame game loads the level bundle generated by Pipeline 3
(`z_legend_game_flutter/assets/tiles/starter/`), spawns the player and zombies from the `Entities` object layer,
and the player can walk to the exit.

All paths below are relative to `neuro-symbolic-level-designer/z_legend_game/z_legend_game_flutter/`.

## 2. Level loading (must also support runtime loading later)
The "Try Out" button (later task) will load a level bundle from the backend URL at runtime. Design for this now:
- `lib/game/level/level_source.dart`: a `LevelSource` with an `AssetBundle` and a path prefix.
  - `LevelSource.bundled('assets/tiles/starter/')` uses `rootBundle`.
  - `LevelSource.network(Uri baseUrl)` uses Flutter's `NetworkAssetBundle`. Implement it, but it is not used yet.
- `lib/game/level/level_loader.dart`: loads `level.tmj` through `TiledComponent.load` using the source's bundle and
  prefix (use the `bundle`, `prefix`, and `images` parameters; do not hard-code `rootBundle` or the default

- The map references an external tileset `tileset.tsj`. If `flame_tiled` cannot load an external JSON tileset,
  add an `--embed-tileset` option to `backend/pipeline/execution/map_compiler.py` and `compile.py` that writes the
  tileset inline in `level.tmj`, regenerate the starter level with it, and keep `uv run pytest` (from `backend/`)
  passing. Report which option you used.

## 3. Coordinates (one place only)
`lib/game/iso/iso_math.dart`: all isometric conversions. Nothing else in the game does projection math.
- Tiled isometric object (x, y) -> grid (col, row): col = x / tileHeight, row = y / tileHeight.
- Grid (col, row) -> world position, matching exactly where `TiledComponent` renders tile (col, row) for this map
  (include the map's horizontal offset: flame_tiled draws tile (0, 0) at the top-center of the diamond).
- World position -> grid (inverse), used for bounds checks.
- Depth priority from grid position (Bob rule section 2).

## 4. Game (`lib/game/`)
- `z_legend_game.dart`: `FlameGame` with `HasCollisionDetection` and keyboard input. `World` + `CameraComponent`;
  the camera follows the player.
- Characters: load sheets and sidecar JSON from `assets/images/characters/`. Read frame size, frame count, fps, and
  anchor from the JSON. Do not hard-code them. Rows are directions in the order S, SW, W, NW, N, NE, E, SE.
  Position each sprite by its anchor (feet), not its top-left corner.
- Player (`PlayerSpawn`): WASD and arrow keys move in screen directions (W = up on screen). Combined keys give the
  4 diagonals, so there are 8 facing directions. Animations: `idle` when still, `walk` when moving,
  `attack` on Space (kills zombies within 1 tile; they play `die` once and are then removed).
  The player cannot leave the map (use the grid bounds from `iso_math.dart`).
- Zombie (`Zombie`): plays `idle`. When the player is within 5 tiles, it walks toward the player and faces the
  movement direction. When it touches the player, the player plays `die` and a "You died - press R to restart"
  overlay appears.
- Exit (`ExitTrigger`): when the player reaches its tile, show a "Level complete - press R to restart" overlay.
- Hitboxes: `CircleHitbox` at the feet for characters and a diamond `PolygonHitbox` for the exit tile.
- Depth sorting: update each character's priority every frame from its grid position.
- Debug overlay (toggle with F1): draw a marker at every object position from the `.tmj`, the player's current
  grid (col, row), and hitbox outlines. I use this to check that objects line up with tiles.
